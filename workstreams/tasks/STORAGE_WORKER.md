## Semantics

1. DNS keys are opaque SHA-256 hexadecimal digests generated by the engine from
   domain/type/view/resolver/ECS. Never store resolver URLs or credentials as keys.
   Validate keys and bound payload sizes. Store UTC Unix seconds for TTL math.
2. Add the `dns_cache` table through migration 0004 and register it normally.
   Existing Python data/tables and previous migrations must remain intact.
   Positive and negative response payloads must both round-trip.
3. A DNS cache row is usable only while `stored_at <= now < expires_at`.
   Never treat future-dated, corrupt or expired data as a valid answer. Define
   errors explicitly; an expired/missing entry is a cache miss.
4. `ip_geo` must remain Python-compatible (`ip,country,isp,checked_at`).
   Read/write checked_at using the existing UTC string format, converting with
   SQLite functions or existing time APIs. Skip expired/future/invalid rows.
   Deduplicate and chunk input IPs to avoid SQLite variable limits.
5. Geo writes are one transaction; country codes/IP addresses must be validated.
   Never cache a failed lookup as a known country. Empty batches are no-ops.
6. Test fresh and legacy migrations, repeated opens, cache expiry boundaries,
   resolver-key separation, invalid/future times, negative payloads, large IP
   batches, and transaction rollback with a failing row.
